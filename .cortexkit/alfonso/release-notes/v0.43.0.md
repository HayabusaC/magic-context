## Rust mode

- **Rolling `ck-mc` back across the single-store change is not supported.** The store now carries a
  `single_store` marker recording that a project's rows were moved out of the module's own database
  and into the host's. Nothing sets the marker in this release; the schema for it ships first so
  that every build which could later meet a migrated store already knows how to recognise one. A
  `ck-mc` build without the single-store readers refuses to open a store that carries the marker
  instead of serving the stale rows left behind: the refusal is terminal, names itself
  (`single_store_marker`) on the module log, on `ck module status` health and on every request that
  would have needed the store, and says which build to run. There is no downgrade path and no
  automatic repair — recovering an older `ck-mc` after the move means restoring the store from a
  backup taken before it.
